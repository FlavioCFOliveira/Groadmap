# Release Notes — Groadmap v1.20.0

**Date:** 2026-10-28
**Type:** Minor — a new command, `rmp skills install`, and graph server fixes; a strict SemVer reading agrees (see [Why This Is Released as `1.20.0`](#why-this-is-released-as-1200))
**Tag:** `v1.20.0`
**Previous release:** `v1.19.0` (2026-10-28)

---

## Executive Summary

Groadmap `v1.20.0` adds `rmp skills install`, which installs the two agent skills
`rmp` ships, `roadmap-manager` and `knowledge-authority`, where Claude Code loads
them. It also aligns the graph server with the recovery and lifecycle contracts of
GoGraph `v0.17.2`: a store killed twice opens again, a store whose recovery was not
clean is refused instead of served, and a fail-stopped engine shuts the server down.

The SQLite schema does not change: databases stay at schema `1.17.0`. `go.mod` and
`go.sum` are unchanged, and the graph engine stays at GoGraph `v0.17.2`. The AI
Agent Contract that `rmp --ai-help` emits gains the `skills` command and one
pitfall, and changes nothing else apart from `tool.binary_version`.

## New Features

### `rmp skills install`

`rmp skills install` (`2f6a484`, `10f14a3`, `38e5d02`; `SPEC/SKILLS.md § Skills
Install Command`, `SPEC/COMMANDS.md § Skills Management`, `DOCS/commands/skills.md`)
replaces the installed copies of both skills with the ones on the repository's
`main` branch.

**When to run it.** Run it after `rmp` has been installed or upgraded, and when the
`rmp-version` a skill declares in its frontmatter differs from the version
`rmp --version` writes. Run it once per such occasion. If the two versions still
differ after a successful run, upgrade `rmp` itself instead of running the command
again: the skills on `main` declare the version of the release `main` carries.

```bash
rmp skills install
```

**What it does:**

1. It downloads one URL,
   `https://github.com/FlavioCFOliveira/Groadmap/archive/refs/heads/main.tar.gz`,
   over HTTPS with the binary's built-in HTTP client. The download follows only
   `https` redirects, honours the standard proxy environment variables, and is
   bounded to 300 seconds and to fixed sizes: 64 MiB compressed, 256 MiB
   decompressed, 16 MiB of selected files, and 1,000 selected entries.
2. It extracts only `skills/roadmap-manager` and `skills/knowledge-authority` into
   a private staging directory, and refuses an archive with an absolute or
   traversing name, a link, a device, a duplicated name, or a skill without a
   `SKILL.md`, before any skills directory is touched.
3. It tries three skills directories, in order, and stops at the first that
   installs both skills:

   | Order | `scope` | Skills directory |
   |---|---|---|
   | 1 | `global` | `<managed settings directory>/.claude/skills`, for example `/etc/claude-code/.claude/skills` on Linux |
   | 2 | `user` | `$CLAUDE_CONFIG_DIR/skills` when set and not empty, otherwise `~/.claude/skills` |
   | 3 | `project` | `.claude/skills` in the current working directory |

   A tier is refused, and left as it was found, when one of its paths is not a
   directory, is a symbolic link, is not owned by the caller (or by `root`, for the
   global tier), or is writable by every user without the sticky bit. Each global or
   user tier not used is reported with a warning on stderr.
4. Inside the chosen directory it replaces both skills through a work directory and
   renames, with rollback. Every other skill is left untouched, and the installed
   skills are never left partially replaced.

**Output.** One JSON object on stdout:

```json
{"scope":"user","directory":"/home/alice/.claude/skills","skills":["roadmap-manager","knowledge-authority"],"source":"https://github.com/FlavioCFOliveira/Groadmap/archive/refs/heads/main.tar.gz","skipped":[{"scope":"global","reason":"cannot create /etc/claude-code: mkdir /etc/claude-code: permission denied"}]}
```

**Properties to know:**

- It is non-interactive and has no confirmation flag. `--yes`, `--force` and every
  flag other than `--help` are unknown flags, refused with exit `2` before anything
  is downloaded. The AI Agent Contract publishes this as the pitfall
  `skills_install_confirmation_flag`.
- It operates on no roadmap and does not accept `-r` / `--roadmap`.
- It never invokes `sudo` and never requests elevated privileges.
- `SIGINT` or `SIGTERM` undoes the swap in progress, removes the temporary
  directories, writes nothing to stdout, and exits `130`.
- **No checksum is verified.** GitHub publishes no checksum for a branch archive.
  The integrity of what is installed rests on the authenticated HTTPS connection to
  `github.com` and on the structural validation of the archive.

Each shipped `SKILL.md` now carries a "Keeping this skill current" section that
states the two occasions above (`10f14a3`).

## Fixes

All five fixes are in `rmp graph serve`. Each is covered by a regression test,
which the fixing commit states fails with its fix reverted. None was re-measured
against a `v1.19.0` binary for these notes.

- **A graph store killed twice, the first time with a torn log tail, opens again**
  (`57714ee`, rmp task #631; `SPEC/GRAPH.md § Engine Construction and Lifecycle`).
  `v1.19.0` restarted the write-ahead log's transaction sequence at `1` on every
  open, so the log could hold two transactions under one number, and recovery then
  refused the store with `op names a node key the commit annex does not bind`. The
  transactional store is now built from the recovery result, and the sequence
  resumes from the recovered maximum. Test:
  `TestServe_ResumesTheTransactionSequenceAcrossATornReopen`.
- **A store whose recovery did not replay the log cleanly is refused** (`57714ee`,
  #632; `SPEC/GRAPH.md § Concurrency and Recovery`). A recovery can return no error
  and still report that it did not replay cleanly; serving such a store could
  acknowledge writes that a restart then lost. `rmp graph serve` now exits `1`
  under `utils.ErrGraphStore`, before the log is opened for writing, with:

  ```text
  Error: graph store error: graph store recovery was not clean; the write-ahead log was left unchanged and the store was not served: <detail>
  ```

  Tests: `TestServe_RefusesAStoreWhoseRecoveryWasNotClean` and
  `tests/test_55_error_string_parity.py`.
- **A fail-stopped engine shuts the server down** (`57714ee`, #635;
  `SPEC/GRAPH.md § Server Diagnostics on Stderr`). The engine fail-stops when a
  commit-time index update fails, and from then on refuses every statement. The
  server recognises it from the error record the engine logs, because the wire
  carries only a masked `UnknownError`. It then stops every further fold, drains
  without the shutdown checkpoint, and exits `1` under `utils.ErrGraphServer` with:

  ```text
  Error: graph server error: the graph engine fail-stopped and refuses every statement; the server has shut down. Restart rmp graph serve to rebuild the indexes from the store.
  ```

  Every acknowledged commit stays durable, and the next open serves it. The client
  whose statement met the fail-stop does not receive this line. Tests:
  `TestServe_AFailStoppedEngineShutsTheServerDownWithoutAFold`,
  `TestFoldGate_RefusesEveryFoldOnceTheEngineFailStopped`,
  `TestFailStopWatch_ActsOnlyOnAConfirmedRefusal`.
- **The store closes the engine after the log writer and before releasing the
  lock** (`57714ee`, #636), so no GoGraph goroutine outlives the server. Test:
  `TestServe_LeavesNoGoGraphGoroutineBehind`.
- **GoGraph's recovery warnings are written in the server's log format**
  (`9c1462f`, #640; `SPEC/GRAPH.md § Server Diagnostics on Stderr`). GoGraph's
  recovery writes its `WARN` record through `slog.Default` and takes no logger
  option. Before the store opened, that record was rendered with the standard `log`
  package's local-time prefix. The server now installs its own logger as the
  default first, so the record carries a UTC `Z` timestamp like every other server
  record. Test: `TestServe_UncleanRecoveryWritesOnlyServerRecordsToStderr`, run
  under a non-UTC `TZ`; `tests/test_55` checks the same under `TZ=Asia/Kolkata`.

## Security

- **`rmp skills install` writes executable agent instructions from the network.**
  It fetches `main` over HTTPS and verifies no checksum, because none exists for a
  branch archive (see [`rmp skills install`](#rmp-skills-install)). It refuses
  symbolic links, foreign ownership and world-writable directories without the
  sticky bit at every tier, writes `0700` / `0600` at the user and project tiers,
  and never requests elevated privileges.

## Internal Changes

These change no output of the binary.

- **New tests.** `internal/skillsinstall` carries 33 Go tests that run against a
  local `httptest` server, with no network and no real user directory; the E2E
  suite `tests/test_79_skills_install_command.py` covers the command (`10f14a3`).
  The recovery and fail-stop regression tests are listed under [Fixes](#fixes).
  `tests/test_55`, `test_60` and `test_70` follow the new error lines and the new
  command.
- **The engine-constructor gate recognises the recovery handoff**, and the test
  helper `WALFrame` exposes each record's transaction sequence (`57714ee`).
- **Documentation and specification.** `README.md` and the new
  `DOCS/commands/skills.md` document the command (`38e5d02`). `SPEC/SKILLS.md`,
  `COMMANDS.md`, `ARCHITECTURE.md`, `DATA_FORMATS.md`, `HELP.md` and `README.md`
  specify it (`2f6a484`). `SPEC/GRAPH.md`, `COMMANDS.md`, `ARCHITECTURE.md`,
  `WEB.md` and `IMPLEMENTATION.md` specify the recovery and lifecycle contracts and
  document three engine limitations (`57714ee`; see [Known Issues](#known-issues)).
- **The shipped `knowledge-authority` skill is re-measured on GoGraph `v0.17.2`**
  (`69090e1`, #639): the socket path limits are corrected to the measured values,
  and the census and integrity queries carry a caution about unlabelled reads
  during a rollback. The release cut aligns both skills with `1.20.0`.

## Known Issues

The list was rebuilt for this release. Each item was verified on this tree, by the
means stated. Every item of the `v1.19.0` list still holds. Three items are new;
they describe GoGraph `v0.17.2`, which `v1.19.0` already used, and `57714ee`
documents them in `SPEC/GRAPH.md` for the first time.

- **Node `id()` values jump across a restart of `rmp graph serve`, and are not
  dense** (#634). The shutdown does not close the transactional store, because that
  close would append to the log on every shutdown, so the identifiers left in each
  reserved batch are skipped. Verified by running both binaries, each against a
  throwaway roadmap in an isolated `HOME`: `CREATE (c:Component {key:'graphstore'})`
  received `id()` `140`, and after a restart `CREATE (c:Component {key:'graphserve'})`
  received `165`, identically under `v1.19.0` and `1.20.0`. No stored element is
  affected; identity is the `key` property, never `id()`.
- **While a write cut by the statement budget rolls back, an unlabelled read can
  observe uncommitted state** (#633). A read such as `MATCH (n) RETURN count(n)`
  run during that rollback is affected; reads anchored on a label or filtered on a
  property value are not, and the exposure ends with the rollback. Verified in
  `SPEC/GRAPH.md § Concurrency and Recovery`, from the measurement made in
  `57714ee`; not re-measured for this release.
- **A write of a `UNIQUE` value that a concurrent transaction is freeing can be
  refused** with `Neo.ClientError.Schema.ConstraintValidationFailed` (#638). The
  shipped clients retry only `Neo.TransientError.Transaction.Outdated`, because
  the same code also reports a genuine violation; the same write run again
  succeeds. Verified in `SPEC/GRAPH.md`; not reproduced for this release.
- **`rmp audit list --help` still says `TASK_STATUS_BACKLOG` carries `null` "from
  'task stat'".** `task stat` cannot write that row since `v1.18.0`. Verified by
  running the `1.20.0` help.
- **`rmp backlog --help` and `rmp backlog list --help` still say no 0-9 validation
  is enforced on `--priority`.** The binary refuses `rmp backlog list -p 12` with
  exit `6` and `Error: validation error: priority must be between 0 and 9, got 12`.
  Verified by running the `1.20.0` helps and the command.
- **`1.20.0` does not re-check sprint membership when it opens a database already at
  schema `1.17.0`**, as `v1.19.0` did not. A violation written by a binary older
  than `1.18.0` stays until a membership command touches the task. Verified in the
  code: `internal/db/` is unchanged since `v1.19.0`; not reproduced for this
  release.
- **`modernc.org/libc` is a later release than `modernc.org/sqlite` requires**
  (`v1.79.1` in `go.mod`, against the `v1.79.0` that `modernc.org/sqlite v1.61.0`
  declares in `go mod graph`). The project accepts the risk deliberately
  (`SPEC/BUILD.md § SQLite Driver Rules`). Verified with `go mod graph`.
- **The web query bar's `EXPLAIN`/`PROFILE` prefix check runs outside the 5-second
  budget**, because the engine's parser takes no context (`internal/web/data.go`,
  `refusePlanPrefix`). The code comment records that the costliest input found at
  the 1 MiB ceiling parsed in 2.44 s to 2.72 s and allocated 1.46 GiB; that figure
  was not re-measured for this release.

## Upgrade Notes

### Step 1 — Install and verify the binary

```bash
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/Groadmap/main/install.sh | bash
rmp --version
# Groadmap version 1.20.0 (commit <commit>)
```

The roadmap database and the graph store need no action: neither format changes.

### Step 2 — Update the agent skills

```bash
rmp skills install
```

Run it once. It replaces `roadmap-manager` and `knowledge-authority` in the first
skills directory that accepts them, and reports which one in its JSON output.
`install-skills.sh` remains available:

```bash
curl -fsSL https://raw.githubusercontent.com/FlavioCFOliveira/Groadmap/main/install-skills.sh | bash
```

### Step 3 — Handle the two new `rmp graph serve` failure lines

A supervisor that restarts `rmp graph serve` should know the two new exit-`1`
lines under [Fixes](#fixes). After the fail-stop line, restarting the server is the
remedy the line names. The not-clean recovery line reports damage to the store on
disk, which is what must be acted on (`SPEC/GRAPH.md § Error Handling and Exit
Codes`, rule 11); the server left every file of the write-ahead log as it found
it.

### Downgrading

A `v1.19.0` binary reads the database and serves the graph store that `1.20.0`
uses, because neither format changes. Downgrading removes `rmp skills install` and
the fixes above.

## Why This Is Released as `1.20.0`

A strict reading of Semantic Versioning 2.0.0 gives `MINOR`, which matches the
owner's decision of 2026-10-28.

- **The release adds backward-compatible functionality.** `rmp skills install` is a
  new command. Measured: the AI Agent Contract of the pre-bump tree, compared with
  that of `v1.19.0`, adds the `skills` command and the pitfall
  `skills_install_confirmation_flag` and changes or removes nothing.
- **The other changes are fixes.** The two new `rmp graph serve` exit-`1` lines
  replace serving a store whose recovery was not clean, and keeping alive an
  engine that refuses every statement. The `v1.19.0` specification promised
  neither behaviour, and its exit-`1` row already covered a store that "could not
  be opened or recovered". These are therefore classified as fixes, not breaking
  changes. The change of format of the recovery warning moves it to the format the
  specification already required.

## What Is Not In This Release

- A correction of the two help texts listed under [Known Issues](#known-issues).
- A re-check of sprint membership on open.
- A retry of the `UNIQUE` refusal under concurrent writes, or a workaround for the
  unlabelled read during a rollback.
- Any SQLite schema change, dependency change, or graph store format change.
- A performance claim: no figure was measured for this release.
